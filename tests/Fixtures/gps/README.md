The Codec 8 fixture is the manufacturer-published first example from
https://wiki.teltonika-gps.com/view/Teltonika_Data_Sending_Protocols#Codec_8
(also reproduced in the official Help with Server FAQ). Its GPS element has
zero satellites, so it must decode successfully and receive a record-count ACK,
but must not enter the live location pipeline.

Other packets generated by HardwareGpsTest are **simulated fixtures**, built
from the manufacturer's documented structures, not real tracker captures.
The CRC check vectors use independently published standard check values for
CRC-16/ARC and CRC-16/X-25 on ASCII `123456789`.

Concox X1 manufacturer manual V1.1, May 10, 2017:
https://www.traccar.org/protocol/5023-gt06/X1-GPRS%20Communication%20Protocol%20V1.1.pdf
Scope: short framing, exact X1 model identifier A001, login 01, heartbeat 13,
position/alarm 34. Extended 7979 photo packets and other GT06 variants are rejected.
The X1 layout table on page 5 omits odometer from the summary but the detailed
field table on page 6 includes it after terminal-info. This adapter follows the
detailed table; real X1 captures are required to settle firmware differences.

GT06 classic v1.8.1 reference (manufacturer-authored, hosted by Traccar):
https://www.traccar.org/protocol/5023-gt06/GT06_GPS_Tracker_Communication_Protocol_v1.8.1.pdf

- `gt06-login-official.hex`: manufacturer's login example, section 5.1.3;
  expected ACK `787805010001D9DC0D0A`.
- `gt06-location-official.hex`: exact published location example, section 5.2.2.
  Its printed CRC 8081 does **not** validate against the printed bytes. It is
  intentionally retained and tested as rejected. A separate simulated test
  recomputes its CRC to verify coordinate conversion and TCP stream handling;
  that corrected test packet is not claimed to be a real device capture.
- `bt50-user-login.hex`: real device login capture supplied by the user on
  2026-10-16, IMEI 864540081540460, checksum EF92. The packet matches classic
  GT06 login structure, not the Mictrack catalogue's unrelated B50 assumption.
  This proves this login variant, not all BT50 packets or firmware versions.

The diagnostic listener sends documented login/heartbeat ACKs only to the IMEI
explicitly passed by its operator. It never writes device/location SQL records,
queues packets or broadcasts them. Other variants (including 0x22) are labeled
unsupported rather than guessed. Tests use loopback and an independent temporary
port; do not treat test fixture output as live remote-device reception.
